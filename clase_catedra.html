1¿Qué construimos?

PhantomDroid-Py es un script de Python que convierte tu PC en un centro de control total de cualquier dispositivo Android, sin apps de terceros y sin root. Todo se apoya en ADB (Android Debug Bridge), la herramienta oficial de Google que ya viene instalada junto a Android Studio.

El script detecta automáticamente el celular al enchufarlo por USB, obtiene su IP WiFi, configura ADB en modo inalámbrico y — lo más importante — te avisa que ya puedes desconectar el cable. A partir de ese momento controlas el celular enteramente por WiFi con latencia mínima.

✅ Resultado final
Un panel interactivo con 54 opciones: gestión de dispositivo, apps, archivos, monitoreo del sistema, espejo de pantalla en tiempo real y administración WiFi.

2Conceptos previos

¿Qué es ADB?

ADB (Android Debug Bridge) es una herramienta de línea de comandos que forma parte del SDK de Android. Permite comunicación directa entre la PC y el dispositivo Android por USB o TCP/IP. Funciona con un modelo cliente-servidor:

Tu script
cliente
→
Servidor ADB
puerto 5037
→
Demonio en el celular
adbd

¿Qué es scrcpy?

scrcpy (Screen Copy) es una aplicación de código abierto creada por Genymobile que transmite y controla la pantalla de Android en tiempo real. Utiliza H.264/H.265 para comprimir el video, logrando latencia de 35–70ms — prácticamente sin lag perceptible.

Modelo de threading de Python

El script usa un hilo de fondo (daemon thread) para vigilar continuamente los dispositivos USB sin bloquear el menú principal. Cuando detecta uno nuevo, actúa automáticamente.

ℹ️ Dato clave
Un daemon thread se destruye automáticamente cuando el programa principal termina, por eso es ideal para tareas de monitoreo en segundo plano.

def _auto_install():
    # Busca si 'rich' ya está instalado usando importlib
    missing = [pkg for pkg in ("rich",)
               if not __import__("importlib").util.find_spec(pkg)]

5Núcleo ADB

run_adb() — la función base

Toda la comunicación con ADB pasa por una única función. Esto evita duplicar código de manejo de errores en las 54 operaciones del menú.

python — run_adb() 
def run_adb(*args, device: str = None, timeout: int = 30) -> Tuple[bool, str]:
    cmd = ["adb"]
    if device:
        cmd += ["-s", device]   # selecciona un device específico
    cmd += list(args)

    try:
        r = subprocess.run(
            cmd, capture_output=True, text=True,
            timeout=timeout, encoding="utf-8", errors="replace"
        )
        return r.returncode == 0, (r.stdout + r.stderr).strip()

    except subprocess.TimeoutExpired:
        return False, "Timeout: el comando tardó demasiado."
    except FileNotFoundError:
        return False, "ADB no encontrado en el PATH."
⚠️ Patrón importante
La función devuelve una tupla (bool, str): el primer valor indica éxito/fallo y el segundo es la salida del comando. Todas las funciones del script usan esta convención.

get_devices() — detectar celulares

python — get_devices() 
def get_devices() -> List[dict]:
    ok, out = run_adb("devices", "-l")
    if not ok: return []

    # Salida de 'adb devices -l':
    # List of devices attached
    # R58MA18PJZX  device  model:SM_A52s  ← USB
    # 192.168.1.5:5555  device            ← WiFi

    devices = []
    for line in out.splitlines()[1:]:   # saltar cabecera
        parts = line.split()
        if len(parts) >= 2 and parts[1] in ("device", "offline", "unauthorized"):
            devices.append({
                "serial":   parts[0],
                "status":   parts[1],
                "wireless": ":" in parts[0],  # IP:puerto → es WiFi
            })
    return devices

get_device_ip() — 3 métodos de fallback

No todos los Android responden de la misma manera. Por eso se usan 3 comandos distintos en orden, usando el primero que funcione:

python — get_device_ip() simplificado 
def get_device_ip(serial: str) -> Optional[str]:
    # Método 1: ip route → busca "src 192.168.x.x"
    ok, out = run_adb("shell", "ip", "route", device=serial)
    if ok:
        m = re.search(r"src\s+([\d.]+)", out)
        if m: return m.group(1)

    # Método 2: ip addr show wlan0 → busca "inet 192.168.x.x/24"
    ok, out = run_adb("shell", "ip", "addr", "show", "wlan0", device=serial)
    if ok:
        m = re.search(r"inet\s+([\d.]+)/", out)
        if m: return m.group(1)

    # Método 3: ifconfig wlan0 (Android antiguo)
    ok, out = run_adb("shell", "ifconfig", "wlan0", device=serial)
    if ok:
        m = re.search(r"inet(?:\s+addr:)?\s*([\d.]+)", out)
        if m and not m.group(1).startswith("127"):
            return m.group(1)

    return None  # No se pudo obtener IP

6Conexión WiFi automática

La función setup_wireless_adb() orquesta el proceso completo para pasar de USB a WiFi en 3 pasos:

1

Obtener IP del celular

Llama a get_device_ip() por USB antes de cambiar el modo de ADB.

2

adb tcpip 5555

Reinicia el demonio ADB del celular en modo TCP en el puerto 5555. Requiere conexión USB activa.

3

adb connect IP:5555

Establece la conexión WiFi. Después de esto, el cable ya no es necesario.

python — setup_wireless_adb() 
def setup_wireless_adb(serial: str) -> Tuple[bool, str]:
    ip = get_device_ip(serial)
    if not ip:
        return False, "No se obtuvo IP. ¿Conectado a WiFi?"

    ok, out = run_adb("tcpip", "5555", device=serial)
    if not ok:
        return False, f"Error tcpip: {out}"

    time.sleep(1.5)  # el demonio necesita ~1s para reiniciarse

    ok, out = run_adb("connect", f"{ip}:5555")
    if not ok or "failed" in out.lower():
        return False, f"Error al conectar: {out}"

    return True, f"{ip}:5555"   # éxito, devuelve "ip:puerto"
ℹ️ ¿Por qué el sleep(1.5)?
Cuando ADB cambia de modo USB a TCP, el demonio adbd en el celular se reinicia. Si intentamos conectar antes de que termine, la conexión falla. 1.5 segundos es suficiente en la mayoría de dispositivos.

7Watcher — detección automática

El watcher es un hilo de fondo que se ejecuta durante toda la sesión. Cada 2 segundos compara el conjunto de dispositivos USB conectados con los que conocía antes. Si detecta uno nuevo, actúa automáticamente.

python — _device_watcher() 
def _device_watcher():
    known_usb: set = set()  # seriales que ya conocemos

    while not _stop_event.is_set():
        devices    = get_devices()
        # Solo los USB que están "online"
        usb_online = {d["serial"] for d in devices
                      if not d["wireless"] and d["status"] == "device"}

        # Diferencia = dispositivos que aparecieron ahora
        new_devices = usb_online - known_usb

        for serial in new_devices:
            ok, result = setup_wireless_adb(serial)
            if ok:
                # Actualiza el estado global de la sesión
                current_device    = result
                wireless_connected = True

        known_usb = usb_online
        _stop_event.wait(POLLING_INTERVAL)  # espera 2s o hasta señal de stop

Cómo se lanza el hilo

python — main() 
watcher = threading.Thread(
    target=_device_watcher,
    daemon=True,          # muere solo cuando termina el main
    name="DeviceWatcher"
)
watcher.start()

9scrcpy — espejo sin lag

scrcpy captura el framebuffer del dispositivo Android, lo codifica en H.264/H.265 directamente en el GPU del celular y lo envía por ADB a la PC donde se decodifica en tiempo real. Por eso no hay lag.

GPU del celular
encode H.264
→
ADB over WiFi
TCP/IP
→
GPU de la PC
decode + render

Opciones configurables del espejo

shell — scrcpy con opciones 
scrcpy \
  --video-bit-rate 8M  # mayor = mejor calidad, más ancho de banda
  --max-fps 60         # limitar FPS para ahorrar CPU
  --max-size 1920      # resolución máxima
  --stay-awake         # evita que el celular bloquee la pantalla
  --record salida.mp4  # grabar la sesión simultáneamente
  --no-audio           # deshabilitar audio si no se necesita
✅ Requisito para el espejo
scrcpy necesita que ADB esté conectado (USB o WiFi) pero no requiere root. Solo activa Depuración USB en el celular.
